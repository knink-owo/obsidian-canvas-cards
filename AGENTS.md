# AGENTS.md

This repository is an Obsidian community plugin. Read this file before changing code.

## Commands

- `pnpm install` — install dependencies.
- `pnpm run dev` — esbuild watch build; writes `main.js` on every change.
- `pnpm run build` — type-check and production bundle. Must pass before committing.
- `pnpm run lint` — ESLint with the `obsidianmd` recommended rules.

A build passing is not evidence that the plugin works. UI or behaviour changes have
to be observed in a running Obsidian instance; see "Verification" below.

## Architecture

- `src/main.ts` — plugin entry point. The default export extends `Plugin`; `onload`
  registers commands, events and the settings tab. Click interception and the
  canvas refresh hook use capture listeners registered per document (main window and
  each pop-out window; see "Canvas DOM sync" below).
- `src/settings.ts` — settings interface, `DEFAULT_SETTINGS` and the settings tab.
- `src/canvas/` — Canvas integration: `internals.ts` (minimal private types/helpers),
  `card.ts` (data model), `binding.ts` (per-leaf DOM sync), `card-index.ts` (card
  search over `.canvas` files, public Vault API), `thumbnail.ts` (first image embed),
  `export.ts` (card → note, public Vault API).
- `src/ui/` — `card-modal.ts` (card popup) and `card-search-modal.ts` (body search).
- `manifest.json` — Obsidian metadata. `id` must equal the install folder name and
  must never change after the first release.
- `versions.json` — map of released version → `minAppVersion`; read by the
  community directory when offering updates.
- `main.js` — generated by esbuild. Never edit or commit it.
- `styles.css` — optional, loaded automatically when the plugin is enabled.

## Hard rules

- The bundle must stay CommonJS (`format: 'cjs'`); Obsidian's loader uses `require`.
- Keep `obsidian`, `electron` and `@codemirror/*` / `@lezer/*` external in esbuild.
- Do not bundle Node/Electron-only APIs into the plugin.
- Only import from `obsidian`; do not reach into Obsidian internals **except** the
  allowlisted Canvas internals described in "Canvas internals exception" below.
- Clean up everything registered in `onload` via the plugin helpers:
  `this.registerEvent`, `this.registerInterval`, `this.registerDomEvent`,
  `this.registerMarkdownPostProcessor`, `this.addCommand`, `this.addRibbonIcon`,
  `this.addSettingTab`. Never leave a raw `setInterval` or unbound DOM listener.
- Respect `minAppVersion`: declarative settings (`getSettingDefinitions`) need
  Obsidian 1.13.0+; legacy `display()` must stay for older minimums. `DeferredView`
  needs 1.7.2+. Pop-out window support needs 1.8.0+.
- Use `requestUrl` from `obsidian` instead of `fetch` (CORS).
- Use `normalizePath` for user-supplied vault paths; prefer `Vault.process()` over
  `cachedRead` + `modify` when editing files.
- Do not use `electron.remote`, `app` internals, or force window focus.

## Canvas internals exception

Canvas has no public extension API, but the plugin's core feature (cards stored on
canvas nodes) requires a few internals. Decision: **S1 / D17** — allow only the
allowlist below, keep it isolated and safe. Evidence and experiment notes live in
`docs/research/m0-runtime-notes.md`; update both this list and that document when
usage changes.

Allowed accesses (only from `src/canvas/**`, never from `ui/**`):

- `workspace.getLeavesOfType("canvas")` → `leaf.view.canvas` (Canvas instance).
- `leaf.loadIfDeferred()` — awaited before reading `leaf.view.canvas` when the
  canvas view was restored lazily (deferred views).
- `canvas.nodes` (Map), `canvas.selection`, `canvas.selectOnly(node)`,
  `canvas.zoomToSelection()`, `canvas.createTextNode(...)`, `canvas.requestSave()`,
  `canvas.posFromClient(point)`, `canvas.wrapperEl`.
- `node.nodeEl`, `node.getData()`, `node.setData()`, `node.setText()`,
  `node.attach()`, `node.render()`, `node.isEditing`, `node.x/y/width/height`.
- Text-node DOM class names used only for hit-testing/CSS: `.canvas-node`,
  `.canvas-node-container`, `.canvas-node-content`, `.canvas-node-content-blocker`,
  `.canvas-node-placeholder`, and states `is-editing` / `is-focused` / `is-selected`
  / `is-dragging`.

Constraints:

- Never `setData` a hand-built object: always spread `node.getData()` first, so
  Advanced Canvas fields (`styleAttributes`, `toFloating`, …) survive.
- Do not patch Obsidian prototypes/methods in v1. If a monkey-patch ever becomes
  necessary, it must use `monkey-around`, be registered for unload, and be
  documented here first.
- Feature-detect every private shape (`leaf.view?.canvas`, `typeof node?.getData`)
  and degrade gracefully; a missing/changed internal must never throw into Canvas
  or lose vault data.
- Prefer read-only access; writes only via `node.setData()` + `canvas.requestSave()`
  or `canvas.createTextNode()`.
- Keep all private access in `src/canvas/internals.ts` (types + helpers) so future
  Obsidian upgrades have one place to fix.

## Canvas DOM sync

Canvas re-creates node DOM and only renders while the view is visible, while our
card state lives in node data. Keep these two in sync without patching Obsidian:

- The single source of truth is `node.getData().canvasCard`; the `.canvas-cards-card`
  class and the corner button are derived, not stored.
- `CanvasBinding` re-applies derived state from data on: node DOM mutations
  (`MutationObserver`), a `30 ms` timer scheduled by `scheduleApply()`, and
  `plugin.applyAppearance()`.
- Data changes that do not touch the DOM (undo/redo shortcuts and the canvas toolbar)
  are caught by per-document capture listeners: `keydown` Ctrl/Cmd+Z/Y and
  `pointerup` inside `.canvas-wrapper` → `plugin.scheduleCanvasRefresh(...)`.
- Never use `requestAnimationFrame` for this refresh: Obsidian pauses rAF in a
  hidden/background window, so the refresh would silently stop.
- Pop-out windows are separate documents: every canvas leaf's `ownerDocument` gets
  the click listeners (see `ensureDocumentListeners`), so cards work there too.

## Submission rules that are easy to violate

- `id`: lowercase letters, digits and hyphens only; no "obsidian"; must not end in "plugin".
- `name`: no "Obsidian", no leading "Obsi", no trailing "dian", no trailing "Plugin".
- `description`: ≤250 characters, ends with `.`, `!` or `?`, no emojis.
- `isDesktopOnly` must be present and accurate.
- GitHub release tag must equal `manifest.json.version`, with `main.js`,
  `manifest.json` and `styles.css` attached.

## Verification before calling work done

1. `pnpm run build` passes.
2. `pnpm run lint` passes.
3. `main.js` exists and is a CommonJS bundle.
4. Version fields agree across `manifest.json`, `package.json`, `versions.json`.
5. UI/behaviour changes were actually observed in Obsidian — reload the plugin,
   open the view/modal/command and look at it.
